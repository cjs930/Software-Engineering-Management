## 二、 課堂核心重點摘要

### 1. 經典軟體流程模型綜合比較 (Process Models Comparison)
課堂方針對三大典型開發模型進行深度比較與特性分析：

| 評估維度 / 特性 | 瀑布模型 (Waterfall) | 增量模型 (Incremental) | 整合與組態 (Integration & Configuration) |
| :--- | :--- | :--- | :--- |
| **核心特點** | 循序漸進，具備嚴謹審查驗證 | 多次疊帶，先交付 MVP 再依反饋擴充 | 高度重用 (Reuse) 現成元件或第三方 API |
| **適用場景** | 需求極度明確、結構化且規範不變動 | 商業模式變動快、需求初期無法完全定案 | 追求快速上市、有現成模組可對接 |
| **品質定義** | 符合規格書 (Specification) 與結構嚴謹性 | 滿足使用者實際痛點與體驗 (User Value) | 依賴組件本身品質與架構整合能力 |
| **技術能力要求** | 團隊需具備全生命週期成熟工程技術 | 考驗高超架構設計力（避免疊床架屋） | 考驗第三方 API 整合與跨平台溝通硬實力 |

### 2. DevOps 流程與 CI/CD 自動化
* **Dev + Ops 雙環循環**：涵蓋 Plan $\rightarrow$ Code $\rightarrow$ Build $\rightarrow$ Test $\rightarrow$ Release $\rightarrow$ Deploy $\rightarrow$ Operate $\rightarrow$ Monitor。
* **自動化效益**：透過腳本觸發 CI/CD（持續整合/持續部署），達成快速發布與即時監控（如 A/B Testing 監控使用者行為反饋）。

### 3. 計畫導向 (Plan-Driven) vs. 敏捷開發 (Agile)
* **計畫導向**：建立於嚴謹 SOP、PDCA 循環與明確文件規範（Input/Output/Entry/Exit 準則）。
* **敏捷開發**：強調彈性與反應力，採用「**漸進式/滾動式規劃 (Iterative Planning)**」（如 Scrum 中的 Release Planning 與 Sprint Planning）。
* **鐵三角與敏捷控管**：專案管理三角（範疇 Scope、時間 Time、成本 Cost）。敏捷透過「固定時間（Sprint 週期）」與「固定資源」，採取「**動態調整範疇 (Variable Scope)**」來確保專案絕不延期（No Delay）。

### 4. 應對變動策略：預期改變 vs. 容忍改變
* **預期改變 (Change Anticipation)**：
  * 在設計階段預估未來變更需求，預先預留彈性介面與組態設定。
  * **拋棄式原型 (Throwaway Prototyping)**：主要用於確立 UI/UX 與需求溝通，確認後即廢棄，避免不良結構進入正式系統。
* **容忍改變 (Change Tolerance)**：
  * 容許於開發過程中吸收變更需求。
  * **演化式原型 (Evolutionary Prototyping)**：從雛形逐步修改演化為最終系統，但需預防範圍蔓延 (Scope Creep) 與架構惡化風險。
